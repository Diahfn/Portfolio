SOAP Integration Truck Activity System
Sample IBM ACE SOAP/XML ESQL

Architecture Flow

Problem
  • Gate system (in-gate, out-gate, weighbridge) ran in complete isolation from the central integration hub
  • Operators manually re-keyed every truck event hundreds of trips/day, causing 5–15 min data lag
  • Billing, yard planning, and customs all operated on stale truck status data
Solution
  • Built a bidirectional SOAP layer on IBM ACE OutboundGateFlow pushes gate events to the hub; InboundStatusFlow handles hub acknowledgements back to the gate system
  • ESQL handles field mapping, type casting, conditional routing, and malformed-payload error paths
Result
  • Manual re-entry fully eliminated gate events propagate in <5s
  • Billing and yard ops gained real-time truck status; data-lag disputes dropped to zero

Staging Table Sync Oracle Database Strategy
Sample Oracle DB IBM ACE ESQL MERGE/UPSERT
Problem
  • 3 upstream services (vessel schedules, container tracking, berth plans) all used plain INSERT into one shared staging table
  • After weeks of operation: thousands of duplicate rows, stale records, dashboards running dedup on every query
Solution
  • Mutable records (e.g. vessel ETAs) → MERGE INTO keyed on business identifiers
  • Full-snapshot data (e.g. daily berth plans) → DELETE + bulk INSERT in a single transaction
  • All sync flows orchestrated via IBM ACE ESQL on schedule
Result
  • Duplicate records → 0; table size stabilized with no unbounded growth
  • Downstream query time ~2× faster no more in-query dedup logic needed

API Gateway Management Kong & IBM API Connect
Sample Kong Gateway IBM APIC API Management

Architecture Flow

Problem
  • 30+ APIs across IBM ACE, Node.js, and legacy backends each with its own auth scheme (basic auth, API key, or none)
  • No rate limiting, no traffic visibility; consumer onboarding required contacting each service owner individually (days of wait)
  • Security review flagged several APIs as publicly exposed without authentication
Solution
  • Kong Gateway deployed as edge proxy: API key + JWT auth, per-consumer rate limiting, upstream routing
  • IBM API Connect for lifecycle management: API publishing, subscription management, self-service developer portal
  • All APIs migrated behind gateway, credentials rotated, unauthenticated endpoints closed
Result
  • All 30+ APIs governed through one enforced layer auth and rate limits cannot be bypassed
  • Consumer onboarding: days → <1 day via self-service portal
  • 0 unauthorized access incidents recorded since rollout
